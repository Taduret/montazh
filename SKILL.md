# Montazh — монтаж под музыку

Скилл собирает ролик из папки с материалом: сам находит склейки в исходниках,
сам определяет темп и биты трека, сам расставляет планы по сетке и рендерит
готовый файл. Человеку остаётся выбрать стиль и длительность и посмотреть
результат.

Всё локально, без облаков и подписок: ffmpeg + python + numpy.

## Когда человек говорит «смонтируй»

Достаточно **одного вопроса** — где лежит материал. Всё остальное бери по
умолчанию и не переспрашивай:

| Что | По умолчанию | Как поменять |
|---|---|---|
| Папка с клипами и треком | — (спросить один раз) | `--src` |
| Трек | самый длинный аудиофайл в папке | `--music` |
| Стиль | `dynamic` | `--style cinematic` / `slideshow` |
| Длительность | ~2 минуты, но не длиннее трека | `--duration 60` |
| Формат | как в исходнике | `--aspect 9:16` для Reels |
| Старт трека | первая сильная доля после интро | `--music-start 32` |

Порядок работы:

1. `python -m montazh doctor` — убедись, что ffmpeg на месте.
2. `python -m montazh preview --src "папка"` — черновик 20 c, 480p (30–60 секунд работы).
3. Покажи черновик человеку, спроси про стиль и длину, если он не сказал.
4. `python -m montazh auto --src "папка" --style ... --duration ... --out out/название.mp4`.
5. Отдай mp4 + постер + сетку кадров, назови цифры: длительность, разрешение, BPM, число склеек.

Если материал лежит не в одной папке, собери папку или передай `--src` на общий
родитель, а трек — через `--music`.

## Быстрый старт

```bash
python -m montazh doctor                       # есть ли ffmpeg и numpy
python -m montazh preview --src "материал"     # черновик 20 c, 480p — проверить ритм
python -m montazh variants --src "материал" --duration 30   # три стиля сразу, на выбор
python -m montazh auto --src "материал" \
    --style dynamic --aspect 9:16 --duration 60 \
    --out out/montazh.mp4
```

В Windows вместо `python -m montazh` можно `montazh.cmd` из папки скилла:
`C:\Users\<имя>\.dsh\skills\montazh\montazh.cmd auto --src "материал"`.

`--src` — папка, где лежат и клипы, и трек. Трек можно указать явно: `--music путь.mp3`.
Рядом с результатом появляются `*.jpg` (постер), `*_sheet.jpg` (нарезка кадров) и
`*.md` (отчёт: BPM, число склеек, длительности).

## Стили

| Стиль | Ритм | Переходы | Когда |
|---|---|---|---|
| `dynamic` | склейка на бит/долю, 0.4–0.8 c | резкие каты, иногда панч-ин | клип, Reels, TikTok, трейлер |
| `cinematic` | такт–два, 1.5–3 c | наплыв 0.3 c, лёгкий зум | атмосферный ролик, портфолио |
| `slideshow` | фраза, 3–4 c | наплыв 0.5 c, Ken Burns | фото, статичные кадры |

Размеры: `--aspect 1:1 | 9:16 | 16:9 | 4:5 | source` (по умолчанию — как в исходнике).
`--height` задаёт высоту кадра в пикселях, `--fps` — частоту (30 по умолчанию).

## Как это работает

```
папка → ffprobe (что внутри)
      → onset-анализ трека (BPM, биты, доли, секции)
      → детект склеек в клипах (шоты + статистика кадра)
      → планировщик (EDL: какой шот, с какой секунды, сколько кадров)
      → параллельный рендер сегментов → сборка → звук (loudnorm) → mp4
```

Шаги разнесены по подкомандам, чтобы пересобирать только нужное:

```bash
python -m montazh analyze --src "материал" --style dynamic   # только анализ + план
python -m montazh auto    --src "материал" --force           # пересчитать кеш
```

Кеш анализа лежит в `.montazh/cache/` и живёт, пока не изменился файл или параметры.
План — `.montazh/plan.json`: его можно править руками и рендерить заново.

## Ритм: правила, которые соблюдает планировщик

1. **Склейка = событие в музыке.** Границы планов ставятся на биты; при сильной
   доле — более «сильный» кадр (движение, крупность).
2. **Длина плана — целое число битов.** Никаких «примерно 0.7 c»: кадры считаются
   целыми, поэтому видео не уезжает относительно звука даже на 200 склейках.
3. **Один шот не идёт дважды подряд** и не возвращается в ближайшие 3 склейки.
4. **Энергия задаёт плотность.** В мощных местах — склейка на каждый бит, в тихих —
   на 2–4 бита. Резкое учащение склеек на смене секции читается как «дроп».
5. **Переход не съедает план.** Наплыв ≤ 25 % длины плана, иначе план «мигает».

Подробнее — [`references/rhythm.md`](references/rhythm.md).

## Проверка результата

После рендера обязательно:

1. `ffprobe` финального файла: длительность совпадает с планом ±0.1 c, есть дорожка AAC.
2. Постер и нарезка кадров глазами: нет чёрных кадров, растяжения, «квадратной» картинки.
3. Отчёт `out/montazh.md`: `cuts_per_sec` и `notes` — если шотов меньше половины
   склеек, материал повторяется, это видно в кадре.

```bash
ffprobe -v error -show_entries format=duration -show_entries stream=codec_type,duration \
  -of default=noprint_wrappers=1 out/montazh.mp4
```

## Что отдавать человеку

- `out/montazh.mp4` — готовый ролик (H.264 + AAC, faststart, −14 LUFS).
- `out/montazh.jpg` — постер.
- `out/montazh_sheet.jpg` — сетка кадров, по ней видно ритм без проигрывания.
- `out/montazh.md` — отчёт: BPM, секции, число склеек, замечания.

Файлы показывай через `present`, а в ответе пиши цифры: длительность, разрешение,
сколько склеек и на каком BPM.

## Ограничения и честные предупреждения

- Источника меньше, чем длина ролика, → шоты повторяются. Скилл пишет об этом в `notes`;
  предложи сократить длительность или доснять материал.
- Склейки внутри одного файла ищутся по разнице кадров: если исходник — один
  длинный дубль без монтажа, шотов будет мало, и ролик станет «один план с зумом».
- Захардкоженные субтитры и логотипы остаются в кадре: это не чистится без
  отдельного прохода (см. `references/ffmpeg-recipes.md`).
- Звук нормализуется в −14 LUFS: для площадок это норма, для кинотеатра — громко.

## Если что-то сломалось

| Симптом | Что делать |
|---|---|
| `Не нашёл ffmpeg` | `winget install Gyan.FFmpeg` (Win), `brew install ffmpeg` (macOS), `apt install ffmpeg` |
| `Не хватает материала под выбранную длительность` | уменьшить `--duration` или добавить клипы |
| BPM явно не тот (вдвое больше/меньше) | `--music-start` + сверить по `*_sheet.jpg`; при живом исполнении сетка переключается на DP-путь автоматически |
| Рендер долгий | сначала `preview`, потом полный; `--workers` под число ядер |
| Ролик «дёргается» на склейках | уменьшить зум: `--style cinematic` даёт плавнее |
